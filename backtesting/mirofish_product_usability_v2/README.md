## 先导为什么改变了产品决定

首轮 v8 出现响应角色错配和自行生成观察期限。修订版改为显式角色编号、第一人称响应，并从用户窗口确定观察期限；旧提示、代码和输出保留。

修订先导的六份情景都已生成，但十二份模型评审中有六份在重试后仍未通过逐字引用核验。部分已通过结构核验的评审也未识别资料之外的数值。原质量评分协议没有通过先导；停止额外付费评分，其未完成状态保存在 report.json。

随后在相同的匿名化数据、24 案例、服务商和总预算内，仅补齐生成回归。此调整发生在先导之后，属于产品排查，不是预注册的质量有效性证明。案例选择为已有匿名回放 001–025，因 016 无已完成决策记录而排除，不按结果或得分挑选。

## 如何读这些指标

- 角色覆盖按已产生决策的角色和全部预配置角色分别计算。前者 100% 不意味着每个原始角色都参与了模拟或被深入讨论。
- 数值规则只寻找事实和观察窗口中未出现相同依据的常见阿拉伯数字及单位，提供复核线索。它不证明幻觉，也不能证明未标记文字正确；分母仅为成功输出的分支。
- 同一个模型生成和评审，先导评分可靠性不足，报告不作质量胜负或预测准确率结论。
- 所有案例复用已有模拟，本轮不验证新角色目标、完整仿真交互收益或真实交易效果。

## 复算与验收

```bash
python3 verify_generation.py
```

只需 Python 标准库，不连接模型，不读取历史结果标签。它校验文件摘要，复核角色、决策、证据引用，并从 cases/ 与 calls.json 重算生成结果和数值标记。

cases/ 保存匿名共用输入、成功输出及有效评审；failures.json 保存结构失败原因，calls.json 保存逐请求用量。generation-stress-protocol.json 解释停止质量评分后的范围；原始协议和第一次先导封存信息也保留。

实际验收可选择并购/监管、财报指引、运营中断三个熟悉事件。检查是否少漏看一方、能否直接复制观察清单，以及有没有一条值得继续跟进的影响路径。
